3. HOW TO USE IT IN THE EXISTING APP
-----------------------------------
   A. Run the repository as a static web app, e.g.
        python -m http.server 8080
      Open http://localhost:8080/
   B. Open Engineering Calculations > External Reference Review.
   C. From a legitimately accessible local EPCC source checkout at the
      pinned commit, choose:
        standards-packs/reference/pipe-sizes.ref.json
        standards-packs/reference/pipe-schedules.ref.json
      They remain in the browser session only and never overwrite masters.
   D. Check each row's validation and pinned-blob identity.
      PINNED_MATCH means the uploaded bytes match the supplied Git revision;
      it is not evidence of engineering correctness or licence rights.
      HASH_UNAVAILABLE / NOT_PINNED_SNAPSHOT must be handled as unverified.
      Only PINNED_MATCH files are eligible for the exact dimensional lookup.
   E. Example lookup: NPS 6, Schedule 40. Review the reported OD,
      nominal wall and calculated nominal ID; absence of a pair is a
      deliberate failure, not zero thickness or an inferred alias.
   F. Optional: also upload iso.pack.json to inspect its governance
      metadata. ISO / IPS / AWP pack workflows are NOT silently applied
      to a converter, its project approval gates or engineering results.
   G. For the MatSEng-style comparison, manually provide P in MPa,
      outside diameter in mm, S in MPa, E, W, Y, corrosion allowance in mm
      and negative mill tolerance %. The two outputs are:
        Legacy MatSEng-style: P*D/(2*(S*E + P*0.4))
        Explicit S/E/W/Y:     P*D/(2*(S*E*W + P*Y))
      Both add CA and apply the same selected mill tolerance.
      This exercise exposes differences in assumptions. It is NOT a
      reproduction of all clauses, exceptions, MAWP or other MatSEng APIs.
   H. Download the provenance receipt for review. It contains file names,
      source SHA evidence and statuses, not the standards tables.

4. APP ASSESSMENT: HOW TO USE THE SOURCES EFFECTIVELY
-----------------------------------------------------
HIGH ROI  — EPCC pipe size / schedule references
   Use as independent candidate dimensions to cross-check Step 4 and
   the existing pipe-wall master. For example, detect wrong NPS mapping,
   OD versus nominal bore, schedule aliasing and missing schedule entries.
   Compare against the governed project material and code edition before
   approving any discrepancy. There is intentionally NO automatic Pull.

HIGH ROI  — EPCC B31.3 / material and reference metadata
   Use to build an engineering evidence checklist, not as an activated
   S/E/W/Y table. The existing B31.3 Factor tab requires exact grade,
   product form, manufacturing route, temperature T1, authority, edition,
   row/table and project approval. Importing a value alone is not enough.
   Protected files can contain proprietary standard data; do not mirror
   without rights and project signoff.

MEDIUM ROI — EPCC flange/valve/fitting references
   Future opt-in dimension and rating discrepancy reviews may benefit
   XML-to-CII component enrichment and mass/length audit. Mass and size
   must remain assigned to the physical component owner; a flange
   rating is not a verified mass or a new restraint/weight authority.

MEDIUM ROI — MatSEng piping/property/fatigue/creep methods
   MatSEng is a useful SECOND-OPINION calculation library on a Python
   service or local engineering workbench. Do not replace the existing
   governed JavaScript B31.3 engine. The pinned core/piping.py assumes
   Y=0.4 and does not model W in its wall formula, unlike v0.65.
   Later integration needs a versioned Python service, dependency
   isolation, unit checks and per-method benchmark/qualification evidence.

LOW ROI  — EPCC ISO/IPS/AWP process governance inside this converter
   These packs govern enterprise work packages, lifecycles and KPIs.
   They do not produce XML-to-CII geometry or B31.3 design factors.
   Preserve metadata as an audit reference rather than adding unrelated
   app tabs or permitting pack-driven changes to converter workflows.

5. NON-NEGOTIABLE ENGINEERING BOUNDARIES
---------------------------------------
   - Existing XML-to-CII parsing, final emitted CII, rigid mass and
     restraint identity paths are untouched.
   - No upstream factor, reference record, schema status or screening
     result is auto-promoted to VERIFIED / PROJECT_APPROVED.
   - No S/E/W/Y material-factor master changes or Step 4 wall Pull.
   - Exact source revision / file hash != approval or licence.
   - No default material, T1, manufacturing route, S/E/W/Y or schedule
     is inferred in the port.
   - No copy of ASME / ISO / other publisher-owned standard tables.
   - The numerical parity function is a simple comparison, not an
     independently certified code implementation.
